## Decision

Rungent is an embedded Python runtime with optional adapters, not an agent platform. The host
application owns authentication, business services, database transactions, prompts, tools, and UI.
Rungent owns the model/tool loop and its externally observable lifecycle.

```mermaid
flowchart LR
  UI["Product UI"] --> SDK["@rungent/sdk"]
  SDK --> HTTP["FastAPI adapter"]
  HTTP --> Runtime["Rungent Runtime"]
  Runtime --> S1["System One shortlist"]
  S1 --> Model["Model adapter"]
  Runtime --> Tools["HTTP allowlist / typed @tool"]
  Runtime --> Store["Memory or SQLAlchemy Store"]
  Tools --> API["Same product HTTP APIs"]
  Ext["External agent"] --> MCP["MCP adapter"]
  MCP --> Tools
```

The preferred host path is `create_openapi_runtime`: allowlisted Console (or product) HTTP
operations become tools, System One picks a **chat / act / sticky** shortlist each step (never
fail-open to the full catalog; see [System One](/docs/systemone)), mutating calls take
`approval="always"`, and the caller's Bearer loops back to the same `/api/*` surface. Hand-written
`@tool` remains available for product-specific glue.

This boundary gives applications direct, typed access to existing services without a sidecar
network hop or duplicated authorization model.

## Standardized lifecycle

```mermaid
stateDiagram-v2
  [*] --> running
  running --> running: model/tool step
  running --> waiting_input: request_input or approval
  waiting_input --> running: user response
  running --> waiting_external: deferred host task
  waiting_external --> running: trusted host completion
  running --> completed: final assistant message
  running --> running: transient provider retry (same model step)
  running --> failed: exhausted provider retries or max model steps
  running --> cancelled: cancellation
```

A session has at most one active Run. The entire Run keeps one monotonic ACS event sequence across
pause/resume boundaries. Approvals persist a validated, normalized tool invocation; resuming cannot
substitute new arguments. A deferred task persists its host task ID and original tool call;
completion is trusted, terminal, and consumable exactly once.

## Packages

| Package | Responsibility |
| --- | --- |
| `rungent` | Agent definition, `@tool`, loop, interactions, ACS, model/store ports |
| `rungent.fastapi` | Four resource-oriented endpoints and SSE transport |
| `rungent.mcp` | Streamable HTTP MCP for the same `@tool` catalog |
| `rungent.sqlalchemy` | Application-owned persistent store |
| `rungent.testing` | deterministic harness tests and real-model application baselines |
| `@rungent/sdk` | headless stream parser, client, and reducer |
| `@rungent/docs` | human docs plus `/llms.txt`, `/llms-full.txt`, raw Markdown routes |

## Deliberate omissions

- No sidecar until an actual cross-process consumer requires it. `rungent.mcp` is an in-process
  adapter, like `rungent.fastapi`.
- No skill router; begin with one product Agent and normal typed tools. `Agent.export_skill()`
  writes a file for an external agent and does not route inside the Runtime.
- No styled chat component; Roasea keeps its design system and renders the headless state.
- No provider-specific event types in the browser.
- No prompt-based safety decisions where deterministic runtime policy can enforce them.
- No automatic production schema creation; migrations remain application-owned.

Add a new abstraction only after two real integrations need the same boundary.
